# Page fit: no short chapter endings

The editor does not want a chapter to end with a few lines alone on its last page, nor a
heading stranded at a page's foot, nor a footnote broken over a page (2026-11-24: "I especially
want to make sure we don't have short chapter endings"). colophon's print check finds all of
these as every PDF is built; this skill clears them. They are warnings, not a release gate, so
nothing stops a book with them — this skill is what does.

## What the check reports

`./fgb pdf BOOK` (and `build`) prints, after each print file's `typst:` line:

- `page: a chapter ends on page N with K line(s)` — K is 1 to 4. The fault to clear first.
- `page: a heading is left at the foot of page N: "…"` — alone, or with one line under it.
- `lulu: WARNING a footnote is broken over to page N: "…"`
- `lulu: WARNING footnote X is set on page N, its marker on page M`

Page numbers are the PDF's, not the printed folios.

## The fix: letter spacing on one chapter

The house way (Owen's Mortification, Calvin's Institutes) is a hair of letter spacing on the
chapter that runs short, never rewording and never layout commands in `chapters/typ` (those
must stay exactly what the TEI gives back). In the book's print file:

```typst
// page fit: the chapter would end on a few lines alone; its letter spacing set so it falls well
#[
  #set text(tracking: -0.01em)
  #include "chapters/typ/chapter-05.typ"
]
```

- **Tighter (negative)** pulls a short ending back onto the page before: the usual cure for
  1–4 lines. **Looser (positive)** pushes it out to a fuller last page (five lines or more); use
  it when tightening can't win the lines back.
- Steps of 0.005em; stay within ±0.015em, where the eye can't see it. Beyond that, ask.
- Change the chapter that is short, or for a heading/footnote fault the chapter holding it.
  A change moves every page after it, so faults can appear further on: always rebuild and check
  the whole book, not just the page you fixed.

## The script

```sh
python3 -I .claude/skills/page-fit/scripts/pagefit.py BOOK            # report: fault -> chapter file
python3 -I .claude/skills/page-fit/scripts/pagefit.py BOOK --fix      # try spacings until clean
python3 -I .claude/skills/page-fit/scripts/pagefit.py BOOK --volume 2 # one volume of a set
```

Run from the books repository's root. It builds with `./fgb pdf`, maps each fault's page to the
included chapter file (by matching the page's text), and with `--fix` writes the wrapper above
into the print file, stepping through spacings (tighter first for a short ending) and rebuilding
until every PDF is clean or the tries run out. Read the diff of the print file afterwards: every
wrapper should carry its comment, and none should be left at a spacing that didn't help (set a
chapter back to no wrapper by hand if the fault cleared some other way).

**Print files made by a script** ("GENERATED BY" in the head: the Institutes'
`source/make_volumes.py`) are not edited; the script prints the spacing to try, and it goes in
that script's table instead (`PAGEFIT = {(volume, modern): {"file.typ": "-0.01em"}}` for the
Institutes), then regenerate and rebuild. For a quick loop there,
`.claude/skills/page-fit/scripts/institutes-try.sh '<PAGEFIT dict>' 1,2` sets the table, regenerates and builds.

## When spacing can't do it

- A chapter that stays short at ±0.015em: try the chapter *before* it (its pages move this
  one's start), or a heading kept with its text by the template. Never reword the author.
- A footnote that Typst keeps breaking: try the chapter's spacing both ways first; if it still
  breaks, the editor can accept it by message in `RELEASE.toml` (`accepted_print`), which is the
  only way such a footnote passes the release's print gate.
- Tell the editor what's left, with the page and the chapter.

## Every time, before a draft goes out

1. Build every output (`./fgb build BOOK`) and read the warnings: no `page:` lines, no
   footnote warnings, all EPUBs pass.
2. Page counts move with page fit, so the covers must be rebuilt in the same build (the spine
   width comes from the page count) — never ship a cover from an earlier build.
3. Copy to Nextcloud by deleting the draft folder and copying fresh: the Nextcloud web app keeps
   showing old copies of overwritten PDFs.
4. Anything that adds space or text anywhere (a publisher's line, spacing under chapter titles)
   means running this again: on the Institutes a little space under the chapter titles made
   three new short endings in volume 1.
